- Contents:
  1. Header: suite date/time, workbook, provider/model/threshold, faults injected, tool version (git commit hash if available).
  2. Summary: totals (PASSED/FAILED/BLOCKED), per-case row with status badge, `designed_outcome` + `outcome_as_designed`, reason, duration, heals, vision clicks.

  string (e.g. `<script>alert(1)</script>` in a reason and a model summary) and assert it appears escaped.
- Status colours must not be the only signal (also show the word PASSED/FAILED/BLOCKED).
- Tests: the report builds from fixture results (PASSED/FAILED/BLOCKED cases, a healed action, a vision click, Clef evidence), with no network
  references in the HTML, escaping, and missing screenshots handled gracefully.
